# 추천 채팅 부하 테스트용 LLM 대체

분리된 개발 테스트 서비스에서만 사용한다. 기본값은 꺼져 있다.

```dotenv
CHAT_LOAD_TEST_MOCK=true
CHAT_LOAD_TEST_SPEC_DELAY_SECONDS=1
CHAT_LOAD_TEST_CARD_DELAY_SECONDS=4
AGENT_LOAD_TEST_DELAY_SECONDS=1
```

지연 단위는 초이며 비동기 대기다. 두 값을 0으로 설정하면 FAST 조건이다. 위 숫자는 예시일 뿐 실측 지연 분포가 아니다. 각 호출과 턴 전체 지연을 관측해 보정한다. 추천 조건은 입력 메시지로 만들고 카드에는 실제 검색 후보의 ID를 사용한다. 검색·임베딩·DB와 카드 후처리는 기존 경로를 사용한다. 카드가 0개면 테스트 데이터와 검색 상태를 확인한다.

`CHAT_LOAD_TEST_MOCK=true` 하나로 추천 채팅·취향 추출·쇼핑 mock을 활성화하며 공통 게이트웨이의 실제 LLM 호출을 차단한다. 이름은 기존 설정과의 호환성을 위해 유지했다. `EXTRACTION_LOAD_TEST_MOCK=true`는 취향 추출만 별도로 시험할 때 사용할 수 있다.

취향 추출은 마지막 사용자 발화(4자 이상)를 근거로 테스트 후보를 생성해 기존 필터·임베딩을 실행한다. 없으면 정상적인 빈 결과다. 이 결과는 실제 취향 분석이 아니므로 테스트 데이터에만 사용한다. 추천 채팅은 실제 후보를 조회하며 DB에 후보가 없으면 카드를 만들지 않는다.

쇼핑 부하에는 `장바구니 보여줘`와 `1번 장바구니에 담아줘`를 사용한다. 담기 요청은 `N번`의 카드 번호를 사용할 수 있으며 실제 추천 카드·상품·재고가 필요하다. 실제 확정 요청은 BE 데이터를 변경할 수 있다. 지원하지 않는 쇼핑 요청은 외부 모델 없이 되묻는 응답으로 끝난다. 책 비교 등은 실제 도구 경로를 실행하지 않으므로 이 응답들을 도구 처리 성능의 성공 표본으로 집계하면 안 된다. extraction에는 별도 지연이 없다.

다른 사용자와 공유하는 서비스에 설정하지 않는다. AI 게이트웨이 바깥에 별도 LLM 호출 경로가 없는지도 배포 버전에서 확인한다. HTTP 연결 및 실제 모델 처리 시간·응답 품질은 측정하지 않는다.

테스트 전 배포 버전과 mock 활성화 상태를 확인하고, 외부 호출이 발생하지 않는지 관측한다. 각 테스트 계정은 별도의 대화방을 사용하고, 종료 후 테스트 데이터를 정리한다. 실제 데이터에 mock 응답을 저장하지 않도록 테스트용 계정을 사용한다. 종료 후 설정을 제거하고 Task를 교체하며 팀과 합의한 대로 테스트 코드를 되돌린다.
