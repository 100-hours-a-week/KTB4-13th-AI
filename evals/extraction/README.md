# ⑤ 취향 뽑기 평가용 대화 묶음

`POST /preferences/extractions`가 대화에서 취향을 제대로 뽑는지 재는 데 쓰는 고정 대화 묶음입니다. 프롬프트나 모델을 바꾸는 PR은 이 묶음으로 잰 결과를 적습니다. 기준과 배경은 [#341](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/341)에 있습니다.

묶음(`cases.json`)과, 묶음을 돌려 코드로 채점하는 실행기(`run.py`, `scoring.py`)가 있습니다. LLM 채점은 아직 없습니다.

## 무엇을 취향으로 보나

대화에 붙인 기대값은 아래 규칙을 따릅니다. 규칙을 바꾸면 기대값도 같이 바꿔야 합니다.

- **뽑는다**: 사용자가 자기가 읽으려고 찾거나 좋아한다고 말한 분위기, 주제, 작가, 늘 지키는 쪽수·가격·출간연도 조건. "나는 이런 걸 좋아해"처럼 직접 말하지 않고 추천을 부탁하기만 해도 뽑습니다(명세 ⑤의 예시가 "…을 찾음"으로 뽑습니다).
- **좋아한 책을 제목으로만 말하면**: 주제로 뽑고 문장에 그 제목을 넣습니다. 사용자가 말하지 않은 그 책의 성격(장르, 저자, 줄거리)은 덧붙이지 않습니다. 책을 찾아 그 책의 벡터를 쓰는 것은 고도화 후보입니다([#343](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/343)).
- **안 뽑는다**: 남에게 줄 책, 책 한 권을 제목으로 찾은 것, 배송이나 번역서·전자책·오디오북처럼 책 정보로 가를 수 없는 조건, 찾을 때만 붙인 쪽수·가격·출간연도 조건, "오늘은", "이번 달은"처럼 이번만이라고 밝힌 것, 말했다가 거둔 것, 조수만 말하고 사용자가 받아들이지 않은 것.
- **문장에 넣지 않는다**: 병명, 소송, 가족의 사정 같은 민감한 개인사.

세기·어디에·핵심어([#395](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/395))는 이렇게 적었습니다.

- **세기**: 좋아함은 양수, 피함은 음수입니다. 크기는 부탁만 했으면 1, 직접 말했으면 2, "진짜", "정말", "완전", "너무", "절대", "무조건"처럼 세기를 높이는 말이나 "팬"이 있으면 3입니다.
- **핵심어**: 뜻을 뒤집지 않는 말로 적습니다("슬픈 결말은 싫어" → 슬픈 결말, 세기 -2). 제목만 말했으면 『』로 감쌉니다. 조건은 정해진 꼴(300쪽 이하, 2만 원 이하, 2020년 이후)로 적고, 늘 지킨다고 말한 것만 뽑으므로 세기는 2 이상입니다.
- **어디에**: 사용자가 말한 범위에 맞는 이름만 받아들입니다. 그 위의 카테고리도 받아들이지만, 말하지 않은 갈래로 좁힌 이름(철학 입문 → 서양 철학)은 받아들이지 않습니다. 고양이처럼 맞는 이름이 없거나 제목만 말했으면 비웁니다.

## 파일

`cases.json` 하나입니다.

| 칸 | 뜻 |
| --- | --- |
| `version` | 묶음의 버전 |
| `kinds` | 종류마다 어느 묶음(`group`)인지와 설명 |
| `cases[].id` | 대화 번호. `<종류>-<순번>` |
| `cases[].kind` | 종류(아래 표) |
| `cases[].about` | 이 대화로 보려는 것 한 줄 |
| `cases[].request` | API에 그대로 보내는 요청 |
| `expect.nothing_found` | 뽑을 것이 없어야 하면 `true` |
| `expect.extractions` | 뽑아야 하는 취향. `type`은 종류, `value`는 기대 문장, `keywords`는 뽑은 문장에 하나라도 들어 있어야 하는 말(찾는 말), `stated`는 사용자가 직접 말한 취향이면 `true`이고 부탁한 내용에서 드러난 것이면 `false` |
| `expect.extractions[].strength` | 기대 세기. -3, -2, 1, 2, 3 가운데 하나. 서버는 0과 -1을 내지 않습니다 |
| `expect.extractions[].applies_to` | 주제에만 있습니다. 어디에로 고르면 맞는 이름(서버 안 카테고리·세부 카테고리, `app/core/categories.py`). 비어 있으면 맞는 이름이 없어 응답도 비어야 합니다 |
| `expect.extractions[].applies_to_must` | 주제에만, 적고 싶을 때만 둡니다. 고른 이름 가운데 이 이름이 하나는 있어야 맞습니다. 위 카테고리만 고르면 틀리는 대화(장르를 다른 말로 부름)에 적습니다([#486](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/486)) |
| `expect.extractions[].keyword` | 맞는 핵심어. 응답의 핵심어가 이 가운데 하나와 같으면 맞습니다 |
| `expect.must_not_extract` | 뽑으면 안 되는 취향 문장. 뜻이 같은 것을 뽑으면 실패 |
| `expect.forbidden` | 뽑은 문장 어디에도 들어가면 안 되는 말 |

`expect.extractions`에 없는 취향을 더 뽑는 것은 사용자가 한 말에 근거가 있으면 실패가 아닙니다. 뽑을 것이 없어야 하는 대화에서는 하나라도 뽑으면 실패입니다.


## 종류

두 묶음으로 나눠 따로 셉니다.

**흔한 대화(`typical`) 74개.** 개수를 실제 대화의 비율에 가깝게 맞췄습니다. 이 가운데 56개(76%)가 뽑을 것이 있는 대화입니다. 조건(`condition`) 5개는 조건을 뽑기 시작하며 더했고([#427](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/427)) 실제 비율과는 상관없습니다.

| `stated` | 좋아하는 것, 싫어하는 것, 늘 지키는 조건을 직접 말함 | 10 | 10 |

| `none` | 추천과 상관없는 말 | 6 | 0 |

**지키는 대화(`guard`) 11개.** 드물지만 틀리면 안 되는 대화입니다. 실제 비율과 상관없이 넣었습니다.

| `kind` | 대화 | 개수 | 기대 |
| --- | --- | --- | --- |
| `overlap` | 이미 저장된 취향과 겹침 | 4 | 겹쳐도 다시 뽑음. 같은 취향을 다른 날 또 말하면 또 냅니다([#425](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/425)) |
| `sensitive` | 민감한 개인사가 섞임 | 3 | 취향은 뽑되 그 말은 문장에 안 넣음 |
| `assistant` | 조수의 말만 취향처럼 보임 | 2 | 안 뽑음 |
| `injection` | 속이는 입력 | 2 | 안 넘어감 |

## 비율의 근거와 한계

- 실제 사용자 대화 기록이 아직 없습니다. 흔한 대화의 비율은 ③ 챗봇 평가([#322](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/322))에서 실제 책 추천 요청 글을 조사해 나눈 구성(주제와 자기 상황을 말하는 요청이 가장 많고, "이 책 같은 책"이 잦음)을 바탕으로 어림한 것입니다.
- 그래서 결과는 종류별로 따로 냅니다. 실제 비율이 나오면 종류별 통과율에 그 비율을 곱해 다시 셀 수 있습니다.
- 대화는 직접 쓴 것입니다. 실제 대화가 쌓이면 바꿉니다.

## 돌리는 법

실행기는 대화마다 API를 같은 프로세스에서 그대로 부릅니다. 서버를 따로 띄우지 않아도 되고, LLM은 `.env`의 설정대로 **진짜를 부르므로 돈이 듭니다.**

모델은 `.env`의 `EXTRACTION_LLM_MODEL_ID`를 쓰고, 비어 있으면 `LLM_MODEL_ID`를 씁니다. 지금까지의 측정은 `openai/gpt-4o-mini`로 했습니다. 어느 모델로 부를지는 돌리기 전에 나오는 줄에서 확인합니다.

```
uv run python -m evals.extraction.run --kinds request --runs 3
uv run python -m evals.extraction.run --kinds request --runs 3 --yes --out result.json
```

- `--yes`가 없으면 LLM 호출이 몇 번인지와 어느 모델인지만 알려 주고 끝납니다. 숫자를 보고 나서 `--yes`를 붙입니다
- 고르기: `--kinds`(종류, 쉼표로 여럿), `--ids`(대화 번호), `--group`(`typical` 또는 `guard`). 없는 이름을 주면 돌리지 않고 끝납니다. 아무것도 안 주면 80개 전부입니다
- `--runs`: 대화마다 몇 번 돌릴지. 같은 대화에도 결과가 달라지므로 한 번 잰 값은 믿기 어렵습니다
- `--out`: 호출마다의 결과(뽑은 문장, 실패 이유, 걸린 시간)를 JSON으로 남깁니다. 묶음 버전과 프롬프트 버전도 같이 적힙니다

결과는 종류별·묶음별 통과율 표로 나오고, PR 본문에 그대로 붙일 수 있습니다.

## 코드 채점이 보는 것

호출 하나는 아래를 모두 지키면 통과입니다.

| 실패 이유 | 뜻 |
| --- | --- |
| `error` | 200이 아님(LLM 장애, 시간 초과, 서버 오류) |
| `format` | 응답의 모양이 명세 ⑤와 다름 |
| `extracted` | 뽑을 것이 없는 대화에서 뽑음. 또는 `must_not_extract`의 문장을 글자 그대로 뽑음 |
| `missed` | 뽑아야 하는 취향인데, 그 `keywords` 중 하나라도 든 문장이 없음 |
| `forbidden` | `forbidden`의 말이 뽑은 문장에 있음 |

찾는 말과 금지어는 띄어쓰기와 대소문자를 보지 않고 견줍니다.

뽑을 것이 없는 대화에도 `forbidden`을 적어 둔 곳이 있습니다. **사용자가 하지 않은 말**입니다. 챗봇이 한 말("힐링"), 남의 취향("야구"), 좋아한다고 하지 않았는데 붙인 "좋아"가 그렇습니다. 그런 대화에서 무엇인가 뽑았을 때 실패 이유로 둘을 가를 수 있습니다.

- `extracted`만 나오면: 사용자가 한 말을 명세보다 더 뽑은 것입니다. 고칠지는 정하지 않았습니다([#377](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/377))
- `forbidden`도 같이 나오면: 사용자가 하지 않은 말을 적은 것입니다. 틀린 것입니다([#378](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/378))

**코드로 보지 않는 것**이 있습니다. 뜻을 봐야 해서 LLM 채점으로 미뤘습니다.

- 종류(`type`)가 맞는지. 맞은 개수는 참고로 셉니다
- `must_not_extract`의 취향을 다른 말로 뽑았는지
- 기대에 없는 취향을 더 뽑았을 때 그것에 근거가 있는지

그래서 코드 채점의 통과율은 실제보다 **후하게** 나옵니다. 이런 호출이 몇 번인지는 결과에 "LLM 채점이 필요한 호출"로 같이 나옵니다.

### 세기·어디에·핵심어

통과·실패에는 쓰지 않고, 결과 표 아래에 맞은 비율을 한 줄로 냅니다. 분모는 찾은 취향(찾는 말이 든 문장이 있는 것) 가운데 이 칸을 적어 둔 것입니다. 찾은 문장이 여럿이면 하나라도 맞으면 맞은 것으로 봅니다.

- **세기**: 부호가 맞은 비율과 크기까지 맞은 비율을 따로 냅니다. 2와 3의 경계는 사람마다 갈려서 크기는 참고로 봅니다
- **핵심어**: 받아들이는 말 하나와 띄어쓰기·대소문자를 빼고 같아야 맞습니다. 그 말을 담은 문장을 그대로 적으면 맞지 않습니다
- **어디에**: 고른 이름이 모두 받아들이는 이름 안에 있어야 맞습니다. 주제만 셉니다

서버는 [#426](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/426)(프롬프트 v4)부터 이 칸을 냅니다. 그 전 프롬프트의 결과는 0%입니다.

## 고칠 때

- 대화를 보태거나 고치면 `version`을 올립니다. 버전이 다른 결과끼리는 숫자를 견줄 수 없습니다.
- 형식은 `tests/test_extraction_eval_cases.py`가 CI에서 검사합니다. 묶음을 돌려 채점하는 것은 LLM 비용 때문에 CI에서 하지 않습니다.
- 채점기와 실행기의 테스트(`tests/test_extraction_eval_scoring.py`, `tests/test_extraction_eval_run.py`)는 가짜 응답으로 돌아서 CI에서 돕니다.
