# ① 검색 평가 묶음

검색(`POST /search`)을 고칠 때 전후를 견주는 데 쓰는 고정 묶음입니다. 검색은 결과가 틀려도 오류가 나지 않아서, 같은 검색어로 다시 재 보지 않으면 나아졌는지 알 수 없습니다. 배경은 [#364](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/364)와 [#495](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/495)에 있습니다.

평가 DB에서 LLM 없이 자동으로 뽑은 사례 455건과, 사람이 쓴 서술형 검색어 40건입니다. 서술형("마음이 편해지는 책")은 맞는 책이 여럿이라 나온 책마다 매긴 점수로 잽니다(아래 "서술형 검색"). 통과·실패는 아직 매기지 않고 숫자만 냅니다.

## 종류

| `kind` | 검색어 | 맞는 것 | 숫자 | 수 |
| --- | --- | --- | --- | --- |
| `title` | 책 제목 그대로 | 제목이 같은 책 | 1등·5등·20등 안 적중률, MRR, 못 찾음 | 300 |
| `title-variant` | 제목의 표기를 바꾼 것 | 제목이 같은 책 | 위와 같음. 바꾼 방법별로도 낸다 | 100 |
| `author` | 저자 이름 | 저자 칸에 그 이름이 든 책 | 위 10권 중 그 저자 책의 비율(평균) | 30 |
| `filter` | 흔한 낱말 + 분야·출간연도·가격 조건 | 조건을 지킨 책 | 조건을 어긴 책의 수. 0이어야 한다 | 20 |
| `nonsense` | 없는 말 | 없음 | 돌아온 권수 | 5 |
| `descriptive` | 주제·분위기·대상·상황을 말로 쓴 것 | 2·1·0점을 매긴 책 | 위 10권 nDCG, 2점·0점 책 수 | 40 |

사례마다 위 20권을 한 번 받아 잽니다. MRR은 정답이 처음 나온 등수의 역수를 평균한 값이고, 20등 안에 없으면 0으로 셉니다.

### 무엇을 맞은 것으로 보나

- **제목은 띄어쓰기·문장부호·영문 대소문자를 빼고 같으면 맞습니다**(`app/core/editions.py`의 `title_key`). 저자는 보지 않습니다. 검색어에 저자가 없으니 제목이 같은 다른 책이 1등이어도 검색은 맞게 한 것입니다. 표본 1,000권 중 17%가 저자가 다른 책과 제목이 같았고, 같은 작품도 판본마다 저자 표기가 달라("발타자르 그라시안", "발타사르그라시안") 저자까지 보면 맞게 찾은 것을 틀렸다고 셉니다.
- 부제를 뺀 검색어는 부제 없는 제목의 책이 나와도 맞습니다.
- 저자는 홈 추천의 작가 관심사와 같은 규칙(`has_author`)으로 가릅니다. "한강"을 찾는데 "한강준"의 책은 세지 않습니다. 결과가 10권보다 적어도 10으로 나눕니다.
- 필터의 분야는 검색과 같은 대응표(`app/core/categories.py`)로 가르고, 출간연도·가격은 구간을 봅니다. 값이 없는 책은 조건을 걸면 빠져야 하므로 어긴 것으로 셉니다.
- 없는 말은 몇 권이면 통과인지 아직 없습니다. 지금은 벡터 검색이 늘 가까운 책을 채워 결과가 나옵니다. 자르는 기준이 정해지면 통과 기준을 답니다.

## 서술형 검색

"마음이 편해지는 책"처럼 주제·분위기·대상·상황을 말로 쓴 검색어 40개입니다([#502](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/502)). 맞는 책이 여럿이라 사례에 정답을 적지 않고, 나온 책마다 매긴 점수(`labels.json`)로 잽니다.

| `facet` | 검색어 | 예 | 수 |
| --- | --- | --- | --- |
| `topic` | 주제 | 우주의 기원에 관한 책 | 7 |
| `mood` | 분위기 | 마음이 편해지는 책 | 7 |
| `audience` | 읽는 사람 | 초등학생이 읽을 과학책 | 6 |
| `situation` | 읽는 상황 | 비 오는 날 읽을 책 | 6 |
| `long` | 조건이 여럿인 20자 이상의 문장 | 수식을 쉬운 말로 풀어 주는 파이썬 통계 입문서 | 8 |
| `mixed` | 둘을 섞은 것 | 초등학생이 읽을 우주 이야기 | 6 |

검색어는 사람이 썼습니다. 26개는 ③ 챗봇 평가 질문(커뮤니티 글과 실제 챗봇 기록을 본뜬 것)을 검색창에 칠 말로 줄였고, 5개는 인계 문서의 예시, 9개는 직접 썼습니다(`source`).

### 점수 기준

제목, 저자, 분류, 소개글 앞 300자만 보고, 검색한 사람이 이 책을 "찾던 책"이라고 할지를 매깁니다. 어느 코드에서 몇 등으로 나왔는지는 감추고 섞어서 매깁니다. 출처를 알면 판정이 기웁니다. 아래 예시는 묶음에 없는 검색어로 실제 검색해 나온 책입니다.

| 점수 | 뜻 | 예 |
| --- | --- | --- |
| 2 맞음 | 검색어가 바라는 것(주제·분위기·대상·상황)을 책이 다룬다. 여러 주제 중 하나로 다뤄도 소개글에 분명히 나오면 2점이다. 조건이 여럿이면 모두 맞는다 | "청소년을 위한 진로 책" → 『(청소년을 위한) 진로 멘토링 38』<br>"바다 생물 이야기" → 『(신기하고 놀라운) 바다 생물』(어린이 그림책이지만 검색어에 대상이 없다)<br>"바다 생물 이야기" → 『바다 속 생물』(소개글은 없지만 제목·분류로 분명하다) |
| 1 조금 | 일부만 맞는다(가까운 주제, 대상이나 형식이 다름) | "청소년을 위한 진로 책" → 『청소년 진로 지도 어떻게 할까: 교사를 위한 … 매뉴얼』(읽는 사람이 교사)<br>"바다 생물 이야기" → 『남도의 섬과 바다 이야기』(생물이 아니라 섬 이야기)<br>"웃기고 유쾌한 소설" → 『인류최강 남사친』(소설이지만 유쾌한지 소개글로 알기 어렵다) |
| 0 아님 | 상관없거나 낱말만 겹친다 | "바다 생물 이야기" → 『바다 이야기』(일본 만화)<br>"청소년을 위한 진로 책" → 『(청소년을 위한) 서양화 읽는 법』(대상만 같다)<br>"웃기고 유쾌한 소설" → 『웃으며 사는 법을 배운날, 삶이 선물이 되었다』(웃음을 다룬 자기계발 에세이) |

- 검색어에 대상(초등학생, 직장인 등)이 있으면 대상이 다른 책은 1점까지. 대상이 없으면 대상은 보지 않는다
- 검색어에 형식(소설, 에세이, 시집, 그림책, 입문서)이 있으면 형식이 다른 책은 1점까지. 주제나 분위기가 맞을 때만 1점이다
- 수험서·문제집·연구 보고서는 검색어가 그것을 찾는 게 아니면 주제가 맞아도 1점
- 조건이 여럿이면 핵심 조건(무엇을 다루는 책인지)이 맞아야 1점 이상이다. 핵심이 틀리면 나머지가 맞아도 0점("편의점에서 일하는 여자가 주인공인 일본 소설"에 찻집이 배경인 일본 소설)
- 컬러링북처럼 마음을 편하게 하려고 만든 활동책은 분위기 검색에서 2점
- 소개글이 없으면 제목과 분류로 매긴다. 제목이 검색어에 분명히 맞으면 2점, 제목이 모호하면 0점
- 같은 책의 다른 판본도 ISBN마다 매기되 같은 점수를 준다

### 숫자

- **위 10권 nDCG**: 등수마다 점수의 이득(2점 3, 1점 1, 0점 0)을 log2(등수 + 1)로 나눠 더하고, 위 10권이 모두 2점일 때의 값으로 나눕니다. 1이면 위 10권이 모두 2점입니다
  - 나눌 값(이상값)을 매긴 책 가운데 가장 좋은 순서로 잡지 않고 고정했습니다. 그렇게 잡으면 2점 책이 하나도 나오지 않은 검색어("비 오는 날 읽을 책"에 제목에만 '비 오는 날'이 든 책이 나온 경우)가 1점 책만으로 1에 가깝게 나옵니다. 고정하면 위 10권이 모두 1점일 때 0.33입니다
  - 맞는 책이 사실상 한 권뿐인 검색어는 그 책이 1등이고 나머지가 모두 1점이어도 0.48입니다. 검색어끼리가 아니라 같은 검색어에서 코드끼리 견주는 데 씁니다
  - 라벨을 더해도 이상값이 바뀌지 않아, 이미 잰 코드의 숫자가 그대로입니다
- **2점 책, 0점 책**: 위 10권 중 그 점수의 책 수(평균)
- **점수 없는 책**: 라벨에 없는 책은 0점으로 계산하고 따로 셉니다. 검색 코드를 바꿔 처음 보는 책이 많이 나오면 그 책만 더 매깁니다

### 점수를 매기는 법

점수는 사람이나 작업하는 세션이 직접 매깁니다. 서버의 LLM이나 팀 API 키는 쓰지 않습니다. 중간 파일은 `evals/search/results/label/`에 생기고 저장소에는 올리지 않습니다.

```
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.label pool --code main=. --code ef200=../ef200
uv run python -m evals.search.label apply --judge "누가 매겼는지, 날짜"
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.label review
uv run python -m evals.search.label apply-review --by "누가 확인했는지, 날짜"
```

1. `pool`: 견줄 코드(아래 "다른 커밋의 코드로 재기"의 worktree)마다 위 20권을 받아 ISBN으로 합치고, 라벨에 아직 없는 책만 검색어마다 섞어 `candidates.md`에 씁니다. 책에는 번호(c01…)만 붙이고, 어느 코드의 몇 등이었는지는 `sources.json`에만 적습니다. 채점이 끝날 때까지 이 파일은 열지 않습니다
2. `candidates.md`를 읽고 `grades.json`의 빈칸에 점수를 적은 뒤 `apply`로 `labels.json`에 넣습니다. 이미 있는 라벨은 덮지 않습니다
3. `review`: 라벨의 10%를 시드로 골라 사람이 확인할 표(`review.md`)를 냅니다. 고친 점수를 `review.json`의 `fixed`에 적고 `apply-review`로 넣으면 본 수와 고친 수가 `labels.json`에 남습니다
4. 검색 코드를 바꿔 점수 없는 책이 많이 나오면 1과 2만 다시 합니다. 이미 매긴 책은 다시 매기지 않습니다

### 매긴 점수

`labels.json`에 838권의 점수가 있습니다(2점 363 · 1점 322 · 0점 153). 검색어마다 main, V1(421a77c), `EF_SEARCH`를 400·200으로 낮춘 main의 위 20권을 합친 책입니다.

- 매긴 것: Claude 세션(claude-opus-5-5), 2026-10-19. 먼저 검색어 5개(100권)를 매겨 사람이 본 뒤 기준을 고쳤고(점수 기준의 "여러 주제 중 하나", 활동책, 소개글 없는 책), 나머지는 고친 기준으로 매겼습니다
- 사람 확인: 84권(10%)을 시드로 뽑아 PR 작성자가 보았고 고친 것은 0권(0%)입니다. 매긴 점수와 이유를 보면서 확인했습니다. 점수를 가리고 따로 매긴 것이 아니어서, 사람과 갈리는 비율은 이보다 클 수 있습니다

## 돌리는 법

평가 DB에 붙여 돌립니다. 평가 DB를 만드는 법은 `evals/feed/README.md`의 "평가용 책 표"에 있습니다. 서버를 따로 띄우지 않습니다. LLM은 부르지 않고 검색어 벡터만 로컬 임베딩 모델로 만듭니다. 이 PC에서는 묶음 전부에 1분 안팎 걸렸습니다.

```
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.run            # 몇 건을 돌릴지만 본다
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.run --yes      # 전부 돌린다
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.run --kinds title-variant,author --yes
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.run --yes --out evals/search/results/main.json
```

- `--kinds`, `--ids`로 사례를 고릅니다. `--yes`가 없으면 부르지 않고 몇 건을 돌릴지만 알려 줍니다.
- 검색은 DB에 쓰지 않습니다. 그래도 다른 책 표로 잰 숫자와 섞이지 않게 이름이 `_eval`로 끝나는 DB에만 돌립니다. 다른 DB에 돌리려면 `--any-db`를 붙입니다.
- 묶음을 만든 책 표와 권수가 다른 DB에 돌리면 결과 위에 주의가 찍힙니다.
- `--out`으로 사례마다의 결과(받은 책 번호 포함)를 파일로 남깁니다. `evals/search/results/` 아래에 두면 저장소에 섞이지 않습니다.

### 다른 커밋의 코드로 재기

`--code`로 다른 커밋의 worktree를 주면 검색만 그 코드로 바뀌고, 묶음과 채점은 이 저장소의 것을 씁니다. 검색은 그 폴더의 `app`만 읽는 파이썬을 따로 띄워 부릅니다. V1 운영 코드처럼 채점에 쓰는 모듈이 없는 커밋도 같은 규칙으로 잽니다.

```
git worktree add --detach ../v1 421a77c
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.run --yes --code ../v1
```

상수 하나만 바꿔 보는 실험도 같은 방법으로 합니다. worktree를 하나 더 꺼내 상수만 고치고 `--code`로 돌립니다. 결과 위의 코드 칸에 `(app 을 고친 채)`가 붙습니다.

## 결과 읽는 법

| 칸 | 뜻 |
| --- | --- |
| 1등 안, 5등 안, 20등 안 | 정답 제목과 같은 책이 그 등수 안에 나온 사례의 비율 |
| MRR | 정답이 처음 나온 등수의 역수를 평균한 값. 20등 안에 없으면 0 |
| 못 찾음 | 20등 안에 정답이 없는 사례 수 |
| ↳ 바꾼 방법, ↳ 소분류 | 표기 변형은 바꾼 방법별로, 서술형은 소분류별로 나눈 줄 |
| 위 10권 중 그 저자의 책 | 저자 검색에서 위 10권 가운데 그 저자의 책 비율의 평균 |
| 조건을 어긴 책 | 필터 검색의 결과 중 조건을 어긴 책 수(어긴 사례 수). 0이어야 한다 |
| 돌아온 권수 | 사례마다 돌아온 권수의 평균. 없는 말에서는 이것만 본다 |
| 위 10권 nDCG, 2점 책, 0점 책, 점수 없는 책 | 서술형 검색의 숫자. 위 "서술형 검색"의 "숫자"에 있다 |
| 시간 | 검색 한 번에 걸린 시간의 가운데값. PC에서 잰 것이라 서버와 다르고, 종류끼리 견주는 데만 쓴다 |

- 200이 아니거나 줄여 답한(`X-Degraded`, 벡터 검색이 2초를 넘겨 키워드만으로 답한 경우 등) 사례는 평균에서 빼고 표 아래에 따로 셉니다.
- 한동안 쓰지 않은 DB에 처음 돌리면 벡터 검색이 2초를 넘겨 줄여 답하는 사례가 생길 수 있습니다(처음 돌린 실행에서 필터 사례 1건). 한 번 돌린 뒤 다시 잰 숫자를 씁니다.
- 종류를 섞은 전체 숫자는 내지 않습니다.

## 기준선

2026-10-19에 평가 DB(책 2,107,214권, 벡터 595,329권)에서 묶음 버전 2로 잰 것입니다. 종류별 숫자는 `baseline.json`에 있습니다.

**V1 운영 코드(421a77c)와 main(9c07e7c)은 495건 모두 위 20권이 같았습니다.** 두 코드의 검색 차이(벡터 검색을 2초에서 끊음, 응답의 `isbn` 칸, 재고 필터)는 결과를 바꾸지 않았고, 이번 실행에서 2초에 걸린 사례는 없었습니다. 아래 표는 두 코드에 같습니다(시간은 main에서 잰 것).

- 제목을 그대로 치면 1건 빼고 1등입니다. 제목이 검색어와 같은 책을 맨 앞에 두는 규칙([#119](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/119)) 덕분입니다. 빠진 1건은 제목에 기호 `Ⅰ`이 든 책이고, 같은 제목을 영문 `I`로 적은 다른 판본이 1등이었습니다([#241](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/241)의 "제목에 기호가 든 책")
- 표기 변형에서 1등을 놓친 13건은 권수를 로마 숫자로 친 것(13건 중 8건, [#241](https://github.com/100-hours-a-week/KTB4-13th-AI/issues/241))과 부제를 뺀 것(20건 중 5건)입니다. 부제를 빼면 같은 시리즈의 다른 권("종이접기 도감: 사라진 공룡")이나 비슷한 제목의 책이 먼저 나옵니다
- 동그라미 숫자, 띄어쓰기를 없앤 것, 영문 대소문자를 바꾼 것은 모두 1등입니다
- 저자 검색은 위 10권의 96%가 그 저자의 책입니다. 30명 중 7명이 1에 못 미치고, 가장 낮은 것은 0.7입니다
- 필터 조건을 어긴 책은 없습니다. 조건이 좁은 1건(에세이, 2010년 이전, 1만 원 이상)은 9권만 나옵니다
- 없는 말 5건은 모두 20권이 나옵니다
- 서술형은 위 10권 중 평균 4.7권이 2점, 1.4권이 0점입니다. 소분류 중에는 읽는 상황(situation)이 가장 낮습니다
- 서술형에서 낮은 검색어는 검색어의 흔한 낱말이 제목에 든 책이 위를 채운 것입니다. "번아웃이 왔을 때"(0.024)는 위 10권이 모두 제목에 "왔을 때"가 든 책이고, "어른이 읽는 판타지 소설"(0.181)은 "어른이 읽는 동화" 같은 책, "술술 읽히는 가벼운 소설"(0.194)은 제목에 "술술"이 든 교양서와 술 안내서가 섞였고, "비 오는 날 읽을 책"(0.333)은 제목에 "비 오는 날"이 든 책뿐입니다

## 책을 고른 규칙

평가 DB에서 벡터와 상품(가격)이 있고 제목이 2자 이상 40자 이하인 책을 ISBN과 시드로 정한 순서로 줄 세워 앞에서부터 고릅니다. 같은 책 표와 같은 시드면 같은 묶음이 나옵니다.

- 제목: 앞에서부터 300권. 제목이 같은 책은 한 권만 씁니다.
- 표기 변형: 제목 표본에서 먼저 고르고, 모자라면 표본 뒤의 책을 같은 순서로 씁니다. 부제가 있는 제목은 0.8%, 끝에 권수가 붙은 제목은 2%뿐이라 300권 안에는 몇 건 없습니다. 드문 방법부터 채우고, 책 한 권은 한 번만 바꿉니다. `of`가 있는 사례는 제목 표본의 그 사례를 바꾼 것입니다.
- 저자: 같은 순서로 책의 첫 저자를 보며, 사람 이름으로 보이고 평가 DB에 그 이름이 든 책이 10권 이상인 사람 30명입니다. 사람 이름은 성으로 시작하는 한글 이름이나 띄어 쓴 외국 이름이고, 편집부·연구소 같은 단체나 역할 말이 든 이름은 뺍니다.
- 필터: 낱말 다섯(사랑, 여행, 마음, 역사, 행복)에 조건 넷(분야, 출간연도, 가격, 셋 다)을 붙였습니다. 분야는 온보딩 값만 씁니다. 검색 요청이 그 값만 받습니다.
- 없는 말: 자판을 아무렇게나 친 것 다섯입니다.

다시 뽑는 명령입니다. 책 표를 읽기만 합니다.

```
DATABASE_URL=postgresql://localhost/bookjeok_ai_eval uv run python -m evals.search.build --catalog-built 2026-10-13
```

## 파일

`cases.json` 하나입니다. 사례 하나가 한 줄입니다.

| 칸 | 뜻 |
| --- | --- |
| `version` | 묶음의 버전. 사례를 고치면 올린다 |
| `top` | 위 몇 권을 보는지(20) |
| `seed` | 책을 줄 세운 시드 |
| `catalog` | 책을 고른 책 표. 만든 날, 책 수, 벡터가 있는 책 수 |
| `cases[].id` | 사례 번호. `<종류>-<순번>` |
| `cases[].query` | 검색어 |
| `cases[].isbn` | 제목을 가져온 책(제목, 표기 변형) |
| `cases[].change`, `of` | 표기를 바꾼 방법, 바꾸기 전의 제목 사례(표본 밖의 책이면 null) |
| `cases[].filters` | 검색 요청에 그대로 싣는 조건(필터) |
| `cases[].facet`, `source` | 서술형의 소분류와 검색어의 출처 |
| `expect.titles` | 이 제목과 같은 책이 나오면 맞다 |
| `expect.author` | 저자 칸에 이 이름이 든 책을 센다 |

## 한계

- 표본은 평가 DB의 분포를 따릅니다. 수험서·교재가 많고, 저자도 실제로 많이 찾는 저자와 다릅니다. 종류별 숫자를 보고, 종류를 섞은 전체 숫자는 보지 않습니다.
- 평가 DB는 운영보다 벡터가 있는 책이 많습니다(평가 DB 595,329권, 운영 467,530권. 10/19 기준). 벡터가 없는 책은 키워드로만 찾혀서 운영과 결과가 다를 수 있습니다.

## 묶음을 고칠 때

- 사례를 더하거나 고치면 `version`을 올립니다. 버전이 다른 결과는 견주지 않습니다.
- 형식은 `tests/test_search_eval_cases.py`가 검사합니다. DB 없이 돕니다.
