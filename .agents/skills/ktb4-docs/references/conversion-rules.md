# 변환 규칙 — 구조·내용은 그대로, 형식만 팀 규칙으로

## 대원칙

**1 원본 페이지 = 1 문서.** 목차·소제목·문단의 소속은 원본 그대로 두고, 문장이 담은 정보도 그대로 둔다. 바꾸는 것은 **형식**(문체 어미·표기·블록 모양)뿐이며, 그 기준은 `style-guide.md` 와 `block-patterns.md` 다.

| 층 | 무엇 | 규칙 | 검사 |
|---|---|---|---|
| 구조 (불변) | 제목의 글자·순서·계층·개수, 문단이 속한 섹션, 페이지 단위 | 섹션 추가·삭제·이동·이름 변경·병합·분할 금지 | `preserve_check` 제목 트리 대조 → 오류 |
| 내용 (불변) | 사실·숫자·조건·부정·한정·범위·주체·순서·버전·예외 예시·코드·식별자·외부 인용문·링크 목적지 | 요약·축약·삭제·새 사실 추가 금지 | `preserve_check` 누락·뜻 바뀜·숫자 → 오류 |
| 형식 (통일) | 섹션 안에서 내용을 담는 그릇 | 아래 1·2단계 적용. 3단계는 파트 요청 시 | `check_docs` 오류 0 |

## 구조 — 바꾸면 안 되는 것

- 섹션(`##` 이하 모든 제목)을 추가·삭제·이동·이름 변경·병합·분할하지 않는다. 제목 글자는 `/ :` 같은 기호까지 그대로 둔다.
- 문단·표·목록을 다른 섹션으로 옮기지 않는다. 같은 섹션 안에서도 순서를 바꾸지 않는다. 예외는 참고 링크 줄을 그 절 끝으로 모으는 것뿐 (`block-patterns.md` #10).
- 한 페이지를 설계·선택 근거·부록으로 나누지 않는다. 여러 페이지를 하나로 합치지 않는다. 긴 예시도 **제자리에서** `<details>`로 접는다. 부록 분리는 파트 결정이 있을 때만 한다 (현재 AI-1 뿐, `decisions.md` #16).
- 절차의 단계 수, 표의 행 수, 목록 항목 수를 바꾸지 않는다.

허용되는 구조 손질은 **"제목처럼 쓴 것을 진짜 제목으로"** 하나다 (결정 #16). 글자와 위치는 그대로 두고 마크업만 바꾼다:

| 원본 | 변환 | 왜 |
|---|---|---|
| `**1. 초기 서비스 규모 정의**` (굵은 줄로 쓴 절 제목) | `### 1. 초기 서비스 규모 정의` | 작성자가 제목으로 쓴 것. 목차·앵커에 잡히게 한다 |
| `<details><summary>인증 · 3개</summary>` (항목을 묶는 바깥 상자) | `### 인증 · 3개` + 안의 항목별 `<details>`는 유지 | 두 번 클릭 → 한 번. 도메인이 목차에 잡힌다 |
| 본문 첫 줄이 페이지 제목을 반복하는 `#`/`##` | 본문에서 빼고 frontmatter `wiki:`·`sources:`로 기록 | 위키가 페이지 이름을 이미 제목으로 보여준다 |
| 최상위 제목이 `#` 또는 `###` | 트리를 통째로 옮겨 최상위를 `##`로 | 계층은 그대로. `####` 이하가 나와도 문서를 나누지 않는다 |

## 내용 — 바꾸면 안 되는 것

| 지킬 것 | 예 |
|---|---|
| 사실·숫자·단위·날짜·버전 | 0.18 RPS, 최대 5분, V2, 2026-09-17 |
| 조건·부정·한정·범위·주체·순서 | 않으며, 만, 이내, 다른 담당자 1명, 먼저 (아래 "뜻이 뒤집히기 쉬운 곳") |
| 예외 예시·빈 결과·오류 응답 | 0건 응답, degraded, `error` 이벤트 |
| 코드 블록 내용, 식별자, 경로, 헤더, JSON 키, 명령어 | `current-release.env`, `X-Degraded`, `POST /search` |
| 외부 인용문(공식 문서 인용), 링크 목적지 | 문구 그대로. 링크 주소는 docs 상대 경로로 바꿔도 목적지는 같아야 한다 |
| ①②③ 같은 참조 번호 | AI 문서의 엔드포인트 번호. 본문 곳곳에서 참조하므로 그대로 |
| 도구·서비스 이름, 개념어의 영/한 표기 | Rollback, 롤백 둘 다 원문대로 (용어 통일은 미결, 결정 #2) |

- 문장을 요약·축약하지 않는다. 문장을 지우지 않는다. 원본에 없는 사실·기준·예시를 넣지 않는다.
- 원본끼리 내용이 다르면 둘 다 그대로 둔다. `decisions.md` 에 기준이 있으면 다른 쪽 문장 바로 아래에 `> 기준: {기준 문서} 값 ({값}) — 결정 로그 MM-DD` 한 줄을 **추가**한다. 기준이 없으면 멈추고 사용자에게 묻는다 (판단이라 대신 정하지 않는다).
- 원문 변경이 꼭 필요하면 `docs/_preserve-overrides.tsv` 에 기록하고 PR에서 파트 승인을 받는다 (맨 아래).

## 형식 — 통일하는 것

### 1단계 표기 (문장은 그대로, 기호와 어미만)

| 항목 | 규칙 |
|---|---|
| 문체 | 문장 끝 어미만 `~한다`로 (`합니다`→`한다`, `입니다`→`이다`, `됩니다`→`된다`, `없습니다`→`없다`). 어미 외 단어는 손대지 않는다. 표 셀 안의 사용자 메시지·에러 메시지 문자열은 데이터라 그대로 |
| 제목 레벨 | 트리를 유지한 채 최상위를 `##`로. 번호는 원본 그대로 (없으면 안 붙인다) |
| 구분선 | `---` `***` 제거. 제목이 이미 구분한다 |
| 코드 블록 | ```` ``` ````+언어. `~~~`는 ```` ``` ````로. 언어 없는 블록은 내용을 보고 지정(`text` 포함) |
| 인라인 코드 | 백틱. `<code>`는 `<summary>` 안에서만 (거기선 백틱이 안 먹는다) |
| 표 | 구분선 `\|---\|`, 빈 셀 `-`, 셀 안 `<br>`·목록 금지(문장은 각주로, 2단계) |
| 숫자·날짜·단위·파트명 | `style-guide.md` #9 형식. 숫자 값 자체는 불변 |
| 링크 | 텍스트가 목적지를 설명하게. 변환된 docs 문서는 상대 경로, 아직 변환 안 된 원본은 위키 URL |
| 강조·이모지·인용 | `style-guide.md` #5. `>`는 참고 링크·주의 1개에만. 설명 문단으로 쓴 `>`는 평문으로 |

### 2단계 블록 모양 (문장은 그대로, 그릇만)

블록마다 정답 모양이 `block-patterns.md` 에 있다. 요약:

| 블록 | 통일 |
|---|---|
| 반복 항목 (엔드포인트·테이블·기술 항목) | `<details>` 1단 + summary 형식 통일 + 안의 레이블 이름·순서 통일 (`입력`→`출력`→`에러`, `설명`→`컬럼 설명`→`컬럼 정의`). summary 바로 아래 같은 내용을 반복하는 표는 남는 정보(권한 등)만 한 줄로 |
| 규칙 나열 | `- **레이블**: 설명` 1단. 레이블은 원문에 있는 것만 쓴다 (없으면 불릿만). "레이블 → 설명" 2단 표도 이 모양으로 |
| 절차 | 번호 목록. 단계 수 그대로 |
| 깊은 목록 | 3단 이상은 2단으로. 하위 조각은 상위 항목 문장 뒤에 `→` 포함해 그대로 이어 붙인다 |
| 긴 셀 | 두 문장 이상인 셀은 첫 문장 + `¹`, 나머지 문장은 표 바로 아래 각주 `¹ …` 로 옮긴다 (문장 그대로) |
| 다이어그램 | 노드 텍스트 15자 이내, 원문 설명은 다이어그램 바로 아래 `노드 \| 설명` 표로 |
| 긴 코드 (20줄 초과) | 접히지 않은 본문이면 `<details><summary>{파일명 또는 한 줄}</summary>`로 제자리 접기. 이미 `<details>` 안이면 그대로 |
| 참고 링크 | 그 절 끝에 `- [텍스트](url)` 목록으로 모은다 |
| 핵심 규칙 목록·공통 규약 | 접지 않는다. 길면 원문 순서대로 `###` 없이 그대로 둔다 (제목 추가는 구조 변경) |

### 3단계 문장 손질 (기본 꺼짐 — 파트가 요청할 때만)

50자 넘는 문장 분할, 조건을 앞으로. 정보는 같지만 글자가 바뀌므로 `문장 변경` 목록으로 파트 확인을 받는다. 원본에 없는 기준을 채워 넣는 것("필요시"→"503이면")은 여기서도 금지다.

## 뜻이 뒤집히기 쉬운 곳 (변환 후 원문과 한 줄씩 대조)

| 종류 | 단어 | 원본 예 |
|---|---|---|
| 부정 | 않, 없, 아니, 금지, 불가 | 자동 Rollback에는 별도 승인이 필요하지 **않으며** |
| 한정 | 만, 뿐, 단 | 수동 Rollback할 때**만** 재승인 |
| 주체 | 다른, 같은, 담당 | 준비한 사람과 **다른** 담당자 1명 |
| 범위 | 최대, 최소, 이내, 이상, 이하, 초과, 미만 | 최대 5분 이내 |
| 순서·중단 | 먼저, 이후, 실패하면, 변경하지 않 | AI 검증 실패 시 App EC2는 변경하지 않음 |
| 버전 | (V2), V3 | 이미지 턴 (V2) |
| 예외 예시 | 0건, degraded, 오류 응답 | 접어도 삭제 금지 |

## 절차

중간 승인 없이 끝까지 진행하고 결과를 한 번에 보고한다 (결정 #15). 멈추는 경우는 "충돌인데 기준이 없을 때"뿐이다.

1. `page-map.md` 에서 원본 파일과 새 문서 제목을 확인한다. 상태가 `보류`면 멈춘다.
2. 새 파일을 만든다: frontmatter(`naming-and-links.md`) + `**요약**` 한 줄(추가) + 원문 전체. 제목 트리는 원본 그대로, 최상위만 `##`.
3. 1단계 표기를 적용한다.
4. 2단계 블록 모양을 `block-patterns.md` 대로 적용한다. 블록이 카탈로그에 없으면 그대로 두고 보고에 적는다 (새 패턴 후보).
5. 원본 충돌은 `> 기준:` 한 줄을 추가한다. 기준이 없으면 여기서 멈추고 묻는다.
6. 검사를 실행한다.
   ```bash
   python scripts/preserve_check.py --docs docs --backup-root backup --group <group>
   python scripts/check_docs.py docs
   ```
7. 오류(제목 트리·누락·뜻 바뀜·숫자)가 0이 될 때까지 고친다. **원문을 지워서 통과시키지 않는다.** `문체 변경`은 정보로만 집계되고, `문장 변경` 경고는 3단계를 켰을 때만 나와야 한다 — 켜지 않았는데 나오면 되돌린다.
8. `page-map.md` 상태를 `변환됨(확인 대기)` 로 바꾸고, `docs/README.md` 목차 표의 해당 묶음 행에 이번에 만든 문서 링크를 추가한다(`(변환 후 추가)` 자리표시자면 지우고 채운다). PR을 만든다.
9. 보고: 검사 결과 요약, 적용한 블록 패턴 목록, 승격한 제목(굵은 줄·summary → `###`) 목록, `문장 변경` 목록(있다면 원본·변환본 나란히). 카탈로그에 없던 블록이 있으면 함께 적는다.

## 승인된 원본 변경

기준값 적용 외에 원문 변경이 꼭 필요하면 `docs/_preserve-overrides.tsv` 에 한 줄 기록하고 PR에서 파트 승인을 받는다.

```text
group	원문에 포함된 문구	사유
cld-3	예시 문구	결정 로그 09-17
```
